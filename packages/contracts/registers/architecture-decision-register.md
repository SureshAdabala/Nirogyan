# Architecture and contract decision register

**Initial decision date:** 2026-08-21; maintained through P9 on 2026-08-28  
**Scope:** locked architecture/contract decisions, compatible implementation-boundary decisions, and explicitly deferred clinical/product/production decisions  
**Authority:** `Implementation-Plan.md`, `Claude-Context.md`, P0A source reconciliation, and the contracts in this package

Statuses:

- **LOCKED** — downstream work must implement this decision or create a superseding ADR/schema version.
- **DEFERRED** — deliberately postponed; deadline and impact are stated.
- **CLINICAL/BUSINESS OPEN** — cannot be decided by engineering; blocks only the stated publication/feature unless noted.

## Locked decisions

| ID | Decision | Rationale and consequence |
|---|---|---|
| ADR-001 | Source precedence is: original Niro clinical artifact → explicit later client/product decision → verified external authority → unresolved clarification. Derived configs never override an original source. | Prevents silent clinical inventions and settles conflicts between old prose, draft configs, and Risk Analysis originals. |
| ADR-002 | JSON Schema Draft 2020-12 is the structural dialect. Instance `$schema:"niro-platform/calculator-version.v1"` remains a legacy discriminator in v1. | All five fixtures validate without metadata edits. A later schema may introduce a resolvable schema URI plus separate `schemaVersion`. |
| ADR-003 | TypeScript is the implementation language across client, server, contracts, and engine. | Removes JS/TS ambiguity in the existing plan. P0A files are data/specifications only; P0B adds TypeScript tooling. |
| ADR-004 | `client` uses Next.js with SSR/ISR for public content and client rendering for the interactive form and `/admin`. Express remains a separate API. | Locks the plan's formerly open SEO decision in favor of its recommendation. |
| ADR-005 | Architecture is a modular monolith with two deployables (`apps/client`, `apps/server`) and shared packages `packages/contracts` and `packages/engine`. | No microservices in v1. `packages/engine` is the sole engine path; stale pre-reorganization engine references are superseded. |
| ADR-006 | The engine is pure, deterministic, server-authoritative, and configuration-driven. Public config projection strips scoring internals and trace. | Preserves scoring secrecy and reproducibility; preview and production must use identical contracts/engine. |
| ADR-007 | Engine semantic v1 is `specs/engine-semantics.v1.md`; there is no implicit rounding, absent-to-false coercion, interpolation, context fallback, domain zero, or score clamp. | Supersedes plan prose that proposed an implicit domain clamp and ambiguous sequential imputation. Clinical ambiguity remains a blocker, not an engine default. |
| ADR-008 | Formula keys get deterministic kebab-to-lowerCamel runtime aliases for fixture compatibility; new Studio output writes explicit symbols. Alias collision is invalid. | Binds Heart/CWS expressions without changing formula text and avoids parser-specific magic. |
| ADR-009 | Aggregate/imputation/formula execution is dependency-graph ordered. Aggregate-dependent imputation is supported. | Required for Diabetes waist imputation, which cannot run under a simple “impute before aggregate” stage order. |
| ADR-010 | Calculator lifecycle is `draft → in-review → approved → published → retired`; `in-review → rejected` is allowed. Protected edits create a new draft version. Rollback publishes a new version, never mutates an old one. | Gives versions explicit state semantics and immutable audit history. A rejected version remains historical and may be cloned to a new draft. |
| ADR-011 | Publishing is atomic: version status/current pointer, audit event, content/version snapshot, review hashes, and revalidation event commit together. Assessments and results also use a transaction or idempotent recoverable state machine. | Supersedes the plan's unsafe statement that multi-document transactions were unnecessary. Every development, integration, and production Atlas target must support transactions. |
| ADR-012 | v1 associated content is embedded in the immutable calculator-version snapshot. A content-only edit creates a new version; independent content revisions are deferred. | Satisfies “calculator and whole associated content” while preserving reproducibility with the simplest v1 model. |
| ADR-013 | Content is structured Markdown/typed blocks with raw HTML disabled and allowlist sanitization. JSON-LD is generated from structured fields; admins cannot paste arbitrary JSON-LD. | Prevents stored XSS and unreviewed structured claims. |
| ADR-014 | Claims use stable IDs and claim-level citations. A page-level bibliography alone is insufficient. Niro sources need artifact locators; external sources need verification and license status. | Makes review and later source expiry actionable. Legacy inline source objects remain draft-compatible only. |
| ADR-015 | A distinct `medical-reviewer` permission protects logic, medical content, citations, units, conversions, disclaimers, and recommendations. Approval is bound to logic/content/citation/measurement/test hashes. | Admin/editor status alone cannot satisfy medical approval. Protected changes invalidate approval. |
| ADR-016 | Required/golden tests are publish blockers. Test cases are part of the immutable published version snapshot, regardless of how drafts are indexed in Mongo. | Resolves the plan's missing persistence contract and prevents warning-only medical tests. |
| ADR-017 | Measurement records are versioned. Published configs embed the exact unit/conversion/bounds/help/source snapshot and record a measurement revision; the mutable library is not a runtime scoring dependency. | Prevents library edits from changing old results and preserves Heart 38.61 versus CWS/library 38.67. |
| ADR-018 | Canonical conversion is `canonical = entered × factor + offset`; factor is finite and positive. No intermediate rounding. Composite representations use typed adapters, not fake factors. | Resolves conversion direction and enables temperature without conflating formula coefficients or composite fields. |
| ADR-019 | Structural, semantic, clinical, and publish-eligibility validation are separate. Publish eligibility is computed and never an editable Boolean. | A JSON Schema pass cannot be described as medical approval. |
| ADR-020 | Public users have no accounts or login. Only administrative roles authenticate. | Final client decision already recorded in root context. |
| ADR-021 | Admin auth direction is short-lived access state plus rotating hashed refresh-session families in httpOnly SameSite cookies, CSRF protection, lockout, revocation, and RBAC. | Locks the security shape; exact library/provider selection belongs to P0B/P4. |
| ADR-022 | Anonymous analytics distinguishes persistent pseudonymous `visitorId` from inactivity/session-scoped `sessionId`. Missing identifiers are not retroactively invented. | Corrects the existing plan's use of persistent localStorage ID as a “session.” |
| ADR-023 | Result/share URLs use random capability tokens, expiry, revocation, deletion, and `noindex`; database ObjectIds are never treated as share secrets. | Resolves the privacy/security contradiction in the plan. |
| ADR-024 | Public analytics may avoid persistent raw IP while security logs may retain minimized/hashed admin-login network evidence under a separate retention policy. | Removes the false global “no IP persistence” statement while preserving privacy separation. |
| ADR-025 | Multi-instance deployments require shared/cache-coherent config invalidation and publish-triggered Next.js revalidation. Scheduled jobs use a platform scheduler or distributed lease, not one cron runner per API instance. | Makes scale-out behavior deterministic. Exact provider/mechanism is deferred. |
| ADR-026 | The 62-calculator/79-measurement catalog is quarantined from import until its conversion, merged-host, mapping, source, licensing, and schema integrity gates pass. `mergedFrom` is provenance only unless functionality is materialized in active fields. | Prevents unsafe bulk import. Core P0B–P12 work may proceed using reviewed fixtures/core data. |
| ADR-027 | Initial engine proof uses a deliberately nonclinical arithmetic fixture, then the Heart base-stage worked example. COVID is not the eventual Reusability Gate calculator. | Avoids treating invented COVID points or a preseeded fixture as proof of clinical validity/reusability. |
| ADR-028 | Schema evolution is versioned. `calculator-version.v1` meaning is immutable; date arithmetic, 2-D lookup, datasets/interpolation, and other incompatible features require a later schema/semantic version. | “Schema freeze” means version immutability, not permanent platform stagnation. |
| ADR-029 | v1 locale is `en-IN`; keys and structured fields are localization-ready. | Enables P0B/P5 without waiting for an internationalization roadmap. |
| ADR-030 | CWS remains draft and is not an initial launch calculator. COVID remains internal/nonclinical. Heart, Diabetes, and Hypothyroid require closure/approval of their discrepancy blockers before publication. | Separates platform readiness from calculator-specific clinical readiness. |
| ADR-031 | P2 clarifies the reserved `points` runtime array as unique direct contributions; aggregate results remain under declared aggregate symbols and are included only when an authored formula references them. | Resolves the wording ambiguity in the v1 aggregation section while preserving the source-authored Diabetes `sum(points) + glycemicIndex` formula without double-counting. |
| ADR-032 | V1 lead capture stores only normalized email plus explicit consent/version and TTL; it MUST NOT link to visitor, calculator, assessment, result, share capability, or health data. | Resolves DEF-002 for v1 with the privacy-minimizing option. Any future linkage requires a new versioned contract, consent, encryption/access/export/deletion policy, and security review. |
| ADR-033 | The P6 core-measurement migration is source preserving and draft-only. It retains every legacy value/source/conflict/NC marker, records `niro-cws.config.json` v2 as the current scoring provenance, and never auto-verifies, invents missing per-value attribution or boundary semantics, or copies calculator scoring into library ranges. | Allows the 40-record core to enter the review workflow without turning legacy research into published medical claims. The 79-record extension remains quarantined. |
| ADR-034 | Public measurement reads select only the highest verified revision per key. `verified` is the persistence/public alias for canonical `approved`; the persistence envelope never changes the P0A status or kind vocabulary. | Prevents duplicate/nondeterministic revisions while keeping the canonical contract authoritative. Draft and retired records never enter public search, detail, relations, or sitemap output. |
| ADR-035 | V1 biomarker `usedInCalculators` is derived only from current published calculator versions. `relatedBiomarkers` means a bounded, stable same-domain taxonomy link—not a clinical association—and must be labelled accordingly. | Avoids trusting incomplete legacy `usedIn` metadata or inventing medical relationships not represented by a reviewed contract. |
| ADR-036 | `rangeContext.specimen` is an optional structured string alongside population, method, timing, and preparation. | The locked P0A prose explicitly required specimen context, but the schema accidentally omitted the field. Adding the optional field restores the intended contract without changing a clinical value or boundary. |
| ADR-037 | The rejected P6 generator revisions 1 and 2 remain immutable draft audit history in the configured development database and are fingerprinted in `data/seeds/core-measurements.audit-history.v1.json`; revision 3 is the only current checked seed. A clean database may start at revision 3, but an existing partial/drifted v1/v2 history or a later revision without v3 blocks seeding. | Preserves the actual Atlas history without treating rejected drafts as clinical truth, prevents chronology backfill, and makes existing-history acceptance independently auditable. No prior revision is rewritten, deleted, or published. |
| ADR-038 | V1 derived measurements fail closed at medical verification and public reads. Full SEM-055 support requires a versioned contract with immutable dependency revision/hash snapshots plus a typed, dimension-aware expression/evaluator contract. | The current measurement schema cannot safely prove cross-record DAG, dependency immutability, or dimensional correctness. The migrated eAG record therefore remains a blockered draft; a partial validator must not create false publish assurance. |
| ADR-039 | One shared non-derived measurement eligibility gate is applied at medical verification and again at the public read boundary. It binds structural formats, controlled unit/dimension pairs, conversion coverage, interval/context/conflict/source semantics, current review evidence/hashes, and an immutable persistence envelope. | Direct, historical, or malformed Mixed documents cannot become public merely because their lifecycle and hashes look approved. Verified content is persistence-immutable; only a metadata-only `verified → retired` transition is allowed. |
| ADR-040 | Synthetic P6 live acceptance may write only with explicit intent to a uniquely named temporary `niro_p6_<nonce>` non-production database. The fixture is canonical, nonclinical, ownership-tagged, transaction-scoped, and cleanup-verified. | Prevents temporary approved-looking fixtures from entering a shared development or production database and makes unknown-commit cleanup auditable. |
| ADR-041 | Public analytics persists only server-allowlisted event fields and canonical published-calculator or verified-measurement identifiers. Arbitrary search text is replaced by `[other]`; fake calculator scope/step/parameter/unit/path dimensions are rejected against the published configuration. Attribution retains only referrer host and UTM source/medium/campaign; IP literals and UTM term/content are rejected. | Prevents public callers from permanently injecting names, addresses, medical phrases, fabricated funnel dimensions, or search-like advertising text. V1 deliberately gives up raw zero-result query discovery; a future content-roadmap feature requires a separate retention-bound, reviewed privacy contract. |
| ADR-042 | Analytics identity is domain-separated HMAC evidence with an explicit key version. Session identity is the default; a sliding persistent visitor exists only when server and browser retention/consent settings agree. Stored visitor-backed and session-fallback events remain in separate partitions even when policy later changes; HLL sketches from different identity bases or key versions are never merged. | Preserves ADR-022, prevents cross-domain joins and reconciliation reclassification, fails closed when browser storage is unavailable, and labels mixed/key-rotation totals as upper bounds instead of presenting false exact users. |
| ADR-043 | Permanent analytics rollups contain only aggregate counts, non-reversible sketches, and cohort-eligible dimensions. Page-path/clinical/search/referrer/UTM/unit cells below the configured 2–100 minimum are discarded before TTL-bound sources expire, suppressed values are disclosed as unavailable, and a replacement rollup must prove its exact UTC/DST-aware source window is complete. | Makes small-cell suppression irreversible and prevents an expired or disabled source from overwriting historical aggregates with false zeroes. |
| ADR-044 | New admin-login security records store domain-separated keyed account and network evidence, never raw attempted email or IP. Startup one-way-scrubs any legacy raw-email field while preserving only opaque keyed grouping evidence. Dashboard group labels are opaque; aggregate failed-attempt totals include disabled/locked-account attempts. | Supports security trends and lockout operations without creating a new long-lived PII store or silently losing high-risk authentication failures. |
| ADR-045 | Historical overview, engagement, funnel, score-intelligence, and lead-trend panels read materialized `analytics_daily` rows; only the labelled active-session value reads a bounded five-minute event window. Security, operations, detailed audit, and capped CSV routes may perform bounded reads of their own retained/operational collections. A separately guarded current-day producer refreshes materialized Today/DAU, and every replacement acquires durable `job_runs` evidence plus a timezone/day `analytics_materialization_locks` lease. | Prevents admin refreshes from rebuilding product metrics or issuing unbounded source scans, while accurately preserving purpose-specific security/operations/export behavior. The second lease prevents overlapping producers or older buckets from overwriting a newer full-day snapshot. P11 still owns the external platform scheduler. |
| ADR-046 | Coarse browser/OS/device/locale dimensions are derived with the bounded in-repository parser. Raw `User-Agent`, `Accept-Language`, `Referer`, and URL query strings are removed from request logs as well as analytics persistence. | Avoids fingerprinting and free-text leakage through the logging side channel while retaining the deliberately coarse operational dimensions required by P9. |
| ADR-047 | First-session referrer/UTM retention is claimed atomically through `analytics_attribution_claims`, keyed only by domain-separated HMAC session evidence with an absolute TTL. MongoDB `_id` uniqueness selects one writer across instances; losing writers strip attribution, and rolling upgrades seed claims from retained attribution-bearing events. | Enforces the once-per-inactivity-session privacy contract under concurrent multi-instance ingestion without storing raw session IDs or attribution text. A failed event write may undercount attribution but can never duplicate or block the clinical/public application path. |
| ADR-048 | Hosted runtimes are immutable OCI artifacts identified by `RELEASE_ID`; production startup and worker commands run the same fail-closed environment contract. Liveness is process-only, readiness includes MongoDB and shutdown state, metrics require a distinct bearer secret, and scheduled producers remain separate processes guarded by Mongo leases. | Keeps scale-out health, promotion, scraping, and job ownership deterministic without binding the repository to a hosting/scheduler/metrics vendor. |
| ADR-049 | Publish/retire cache propagation uses the transactional `cache_invalidation_events` outbox plus an independently scheduled leased dispatcher. Delivery is an HMAC-authenticated, timestamp-bounded v1 message to a server-only Next endpoint that accepts only the event's allowlisted calculator/biomarker/sitemap scope. | Provides a provider-neutral retry/idempotency protocol without exposing a public purge primitive. Production still requires a shared/coherent Next cache or proven all-replica fan-out; the reference client stays single-replica until that external condition is met. |
| ADR-050 | Atlas restore acceptance is non-destructive: restore to an isolated target, use a distinct read-only verifier credential, assert the exact database/target label, verify required collections/TTL indexes and critical references, and retain external RPO/RTO evidence before operator-approved cleanup. | Prevents a drill from overwriting production or turning an application script into a destructive Atlas-management tool. Backup enablement and a completed restore/rollback drill remain external evidence, not something repository tests can claim. |

## Clinical/business open decisions

These are recorded, not guessed:

- CWS rejection/stratified-range status and all CWS missing-domain/range/category decisions
- Heart sex applicability/coefficient provenance, endpoint/floor/category semantics, cap/validity, non-HDL, and vascular age
- Diabetes age/HbA1c/FBS/PP boundaries, empty glycemic group, waist fallback, activity source confirmation, and scale
- Hypothyroid symptom grouping and unknown/partial assessment behavior
- COVID's only permissible use beyond an internal fixture, if any
- exact public population wording for each calculator
- legal copy and medical reviewer organization

They block publication of the affected calculator or feature, not P0B repository scaffolding.
